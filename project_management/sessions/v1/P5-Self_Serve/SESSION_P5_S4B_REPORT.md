## What shipped

### 1 · The guard — first commit, and the laptop was the machine that was wrong

S4a made the **worker** the author of `connected_catalog.parquet`. The laptop does not have that
file, and `data_layer.py:2409` returns `read_demo_manifest().clear()` when it is absent — an empty
frame, silently, by design, because every store had none until the first connect. So `_catalog()`
succeeds and quietly loses N.

**Measured live, read-only, today: laptop `_catalog()` = 32 ids, production `league_catalog` = 33,
orphan `1258181662160719872`** — S4a's Rex Lumber. `assert_catalog_covers_postgres` compares the id
**sets** and raises before the `TRUNCATE` in `reload_manifest()` and before the DROPs in `load()`.

**Why `--verify` never caught it, stated because it is the whole point:** `--verify` compares
`count(*)` and `count(DISTINCT league_id)`. It has never compared the id *sets*. A guard is a new
comparison, not a louder version of an existing one.

**The codebase was instructing the operator into the loss.** `_assert_columns_live`'s remedy string
printed `build_db --emit && build_db --load && fly deploy` — trap 1 from the brief — and it is
reached from `_copy_slice_tx` on **both** machines. A guard that intercepts a command while the
codebase keeps printing it has only moved the trap, so the remedy is now machine-aware.

**And the honest remedy is not the obvious one.** Copying `connected_catalog.parquet` down to the
laptop is **not** sufficient: `load()`, `load_league` and `_disk_expectations` are all skip-if-absent
(`build_db.py:638-639`, `:596-597`, `:656`), so without each connected league's `derived/league`
artifacts they would get a catalog row and **zero data rows** — the same loss, quieter. **The full
`--load` has moved to the worker**, the second artifact after `--verify` to change machines and for
the same reason. `--emit` stays on the laptop: it writes a git-tracked source file.

### 2 · The `jobs` table — and two brief corrections found before writing it

In `api/auth_schema.sql`, because `serve/schema.sql` is generated by `--emit` and applied by
`--load`, **which DROPs every table it names** — confirmed by counting: 15 `CREATE TABLE`, 15
`DROP … CASCADE`, exactly paired.

**The brief said adding a name to `_TABLES` inherits "the column and cascade assertions". Half of
that is false.** `_verify_cascades` iterates `_CASCADE_FKS` (`init_auth_schema.py:81`); `_TABLES`
drives only the column dump and the leaked-into-schema.sql check. A table added to `_TABLES` alone
has its FK asserted by nothing. `jobs` is in both lists.

**`_ORPHANS_SQL` mis-handled a nullable FK**, and `jobs.requested_by` is the first one here.
`LEFT JOIN auth.users u ON u.id = t.{col} WHERE u.id IS NULL` counts a row that never named a user as
an orphan — so every hand-enqueued job, which is every job in S4b, would have failed `--verify` on
correct data. The two existing entries were safe only because `user_leagues.user_id` is `NOT NULL`
and `app_users.id` is a primary key. Fixed with `AND t.{col} IS NOT NULL`.

**The fields, and why.** `league_id`/`season` are the payload — `onboard(lid, season)` takes exactly
those, so a job is re-runnable from its own columns. `state` carries all eight values with **no
per-stage semantics**; `validating` is a slot S5 fills. `error` + `state` are what make `failed` and
`rejected` legible without logs: **`rejected` is a deterministic refusal that retrying cannot
change, `failed` is retryable.** `attempts`/`leased_by`/`lease_expires_at` are the lease.
`created_at`/`started_at`/`finished_at`/`updated_at` are DoD 2 — and `updated_at` is the **first in
this repo**, so this establishes a convention rather than following one; every transition sets it in
code, not in a trigger.

**`id` is `uuid`, not `bigserial`, and the rule was already in the file** — internal-only →
bigserial, client-held → uuid. `app_users.id` is uuid because a client holds the token's `sub`;
`signup_attempts.id` is bigserial because nobody outside the server sees one. S4c puts this id in a
URL. A sequential id is also an enumeration oracle for **volume** — how many leagues connected and
how fast — even with S4c's authorization correct, which is exactly what S2b's identical-404 design
exists to prevent; and it invites `ORDER BY id`, which breaks silently the first time a priority
column exists. **The lease orders by `created_at`.**

**`kind` ships; the dossier executor does not.** S4d enqueues refresh jobs, so the second class
arrives before this brief's ink is dry, and one column now beats a migration later on a file with no
migration story. The Manager Dossier fan-out (80s / 248 Sleeper calls) and flipping `panels_manager`
are S4c's — **S4a finding G says "S4b's deferred job flips this row to True", and the S4b brief
never mentions it.** That contradiction is reported rather than silently resolved. Finding G's own
reasoning settles it: the flag is False *because* the data does not exist, so it flips in the session
that makes it true.

**The state CHECK is added by an explicit `DROP`/`ADD CONSTRAINT`**, not inside `CREATE TABLE IF NOT
EXISTS`, which is a no-op on an existing table — the S2a-audit F2 trap one level down, at the
constraint. Adding S6's next state is now a one-line edit that actually reaches production.

### 3 · The lease — the correctness is in the SQL

```sql
WHERE (state = 'queued' OR (state = ANY(%(running)s) AND lease_expires_at < now()))
  AND attempts < %(max)s
ORDER BY created_at LIMIT 1 FOR UPDATE SKIP LOCKED
```

**The parentheses are load-bearing.** `AND` binds tighter than `OR`, so without them the attempt cap
applies only to the reclaim branch and a `queued` row leases without limit — and a graceful SIGTERM
release puts a row back in exactly that state. Proven by **behaviour**, not by reading the string.

**`LEASE_SECONDS = 120`, renewed at every stage transition**, so it only has to exceed the longest
single *stage* rather than the whole job: ~12× S0's measured 8.4–10.3s end-to-end run, and a killed
worker's league is reclaimable in two minutes with nobody intervening. **Correcting the brief: the
80s dossier fan-out is not on this path** — `run_chain`'s `dossiers` defaults to `False` and
`onboard()` never passes it (`onboard_league.py:137`, `:365`), so that stage is unreachable from a
queued job. Renewal covers it if it ever is.

**Idempotency, verified rather than inherited — and the verification found a bug.** See §5.

### 4 · The worker process

`CMD ["sleep","infinity"]` → `python -m application.data.serve.worker_loop`. Still a job box: no
HTTP, no health check, nothing listening.

**`SystemExit` is a `BaseException`, not an `Exception`.** `onboard_league` signals all five of its
refusals with `SystemExit` (`:78, :102, :167, :333, :358`), so a loop written with a bare
`except Exception` would catch **none** of them and the process would exit on the first out-of-scope
league. It is handled explicitly and first, and the fact is now an executable assertion in the gate
rather than a comment.

Classifying by **stage** was considered and rejected: it would send `:167` (first on its scoring key)
and `:358` (wrong season) to `failed` and burn the retry cap on refusals that can never succeed.

**`STORE_ROLE=worker` is asserted at startup and the loop refuses to lease without it** — but it
**idles rather than exits**, and so does a missing `DATABASE_URL`. An exiting process makes the
machine crash-loop, and you cannot `fly ssh` into a crash-looping machine to fix the config that
caused it. This box has no other door.

**Waiting for work: `LISTEN` + a 60s safety-net poll.** NOTIFY is fire-and-forget, so one sent while
the worker is reconnecting is **lost**; without a periodic wakeup that job would sit in `queued` for
ever. The wakeup also runs the reaper and is what turns a dead socket into a visible error instead of
an indefinite block — the connection sets TCP keepalives and a `statement_timeout` for the same
reason. **This forecloses moving the worker to the transaction pooler**, where a LISTEN registration
does not survive; recorded in `api/.env.example` and `config.example.py`, because it would not error
— the worker would simply, silently, stop being woken.

## Two latent defects the queue made reachable — both fixed here

Neither is optional, and neither is the release valve: shipping the loop without them means the first
real crash leaves a permanently un-onboardable league or a truncated season that reads as `ready`.

**A · A crashed COLD run was permanently un-onboardable.** `write_connected_league` runs *after*
`run_chain` (`onboard_league.py:376` vs `:365`), so a crash anywhere in the ~10s chain leaves the
three on-disk directories and **no** catalog row. `classify()` then missed the connected catalog,
`assert_cold` found the directories, and the league was refused — by every route, for ever. Under the
queue that refusal is a `rejected` job, which is **terminal by design**, so the first crash on a real
user's league would have been the last time it could ever be connected.

`classify()` now separates **recorded** warmth (a registry or catalog row — somebody *decided* this
league belongs elsewhere) from **on-disk** warmth (the wreckage of a run, which decided nothing) and
returns `resume` for the second. `assert_cold` is deliberately unchanged: `bench_cold_league` needs
it to refuse both, because a benchmark aimed at a half-built league measures the gates, not the work.

**B · A truncated fetch read as complete — the risk register's exact failure.**
`harvest._raw_present` (`harvest.py:91-95`) is true on config + teams + **week one**, while
`_pull_raw` writes every completed week inside `sleeper.backfill`'s loop. So a run that died at week
6 of 14 left the gate saying "present" over half a season; the join joined only the weeks whose files
existed, and the league would go on to get a spine, a schedule, a catalog row, a Postgres load and
`state='ready'` — **on a truncated season.** Nothing compared joined weeks against
`report["target_week"]`.

`_missing_raw_weeks` asks Sleeper how many weeks are actually complete, via
`_determine_completed_weeks` — **the same function `backfill` uses**, so the two cannot drift — and
bounds it by `_reg_end`. The fetch stage **repairs rather than refuses**, because completing an
interrupted fetch is what a retry is for. It cannot false-positive on a live mid-season league:
`completed_weeks` tracks the real clock, so a league that has played three weeks expects three.

**This is what "verify the claim rather than inheriting it" turned up.** The brief said idempotency
was already paid for because a re-onboard is a proven no-op. That is true of a *completed* run and
false of an *interrupted* one, and the queue is what makes interrupted runs routine.

## Proof

| gate | result |
|---|---|
| `check_store_boundary` | **32/32**, up from 24; `--prove-bites` fails all **11** |
| `check_store_boundary` live half (read-only) | refuses the real **33-vs-32**, naming `1258181662160719872`; permits when the sets agree |

| `check_onboard` | **23/23**, up from 20 (three new `resume` legs); `--prove-bites` still fails its reverted legs |
| local worker smoke test | refuses to lease with `STORE_ROLE` unset and **idles**; connects and waits with it set; SIGTERM → exit in **2s** |
| damage check (`git status` under `snapshots/`) | **clean**; `jobs` back to 0 rows; `league_catalog` still **33** |

**The live lease legs are a real concurrency proof, not a string comparison.** `SKIP LOCKED` cannot
be exhibited by a fake cursor, so those legs use two *uncommitted* connections: A holds a row lock, B
must get a **different** row rather than blocking. Also proven live: an expired lease is reclaimed
with `attempts` climbing (1 → 2); a `queued` row at the cap is **not** handed out (the parenthesis
proof); `reap` buries an abandoned job as `failed` with the reason in `error`; a graceful release
**refunds** the attempt (else every `fly deploy` would burn one of a job's three lives on a job that
never failed); one active job per `(league, season)` is enforced while a finished league can be
re-submitted; and a `NOTIFY` woke a listener in <0.01s.

Throwaway rows only, swept on **exact** ids — never `LIKE`, because `_` is a LIKE wildcard and
`__QUEUECHECK%` would match real league ids. CODING_BIBLE §5's rule applied to a row rather than a
file, which is S4a finding D's shape.

**The local smoke test found a real bug.** SIGTERM while blocked in a single 60s `notifies()` did not
interrupt it, and the process had to be SIGKILLed. Every `fly deploy` would have hung to
`kill_timeout` and stranded the lease it was meant to hand back. The idle wait is now served in 5s
slices — no extra SQL, notifications still wake it instantly — and shutdown measures **2s**.
`fly.worker.toml` states `kill_timeout = "30s"` rather than inheriting the 5s default; the 120s lease
expiry remains the backstop.

**Two assertions I wrote wrong before getting them right**, recorded because both are the same
mistake: **prose that describes a statement is not the statement.** The "guard is wired in before the
destructive statement" check first searched raw source and matched the *comment* above the call
(`# BEFORE the TRUNCATE`) and the *docstring*; matching any string constant then matched
`reload_manifest`'s own error message, which also says "TRUNCATEs" and sits above the call. Both
reported correctly-placed code as broken. It now matches the **call** that does the damage.

### The kill drill, and the first attempt at it proved nothing

**The drill needs the fetch to do real work**, and the way to force that is *not* the S3 technique:
`compute_spine._compute_league` (`:114-127`) and `export_schedule.run` (`:43-49`) have **no skip at
all**, so clearing the spine changes nothing here — S3's clear-the-spine trick applied to
`weekly_refresh`, which does skip. The only two real skips are `run_chain:151` (raw) and `:182-185`
(join). So the drill deleted **matchups weeks 2–18 from the volume, leaving week 1** — which is
precisely defect B's shape, because `harvest._raw_present` is true on week one alone.

**The first drill run killed nothing and reported success.** `pkill -9 -f worker_loop` is a no-op on
this image: `python:3.13-slim` ships **no procps**, so there is no `pkill` and no `pgrep`. The command
failed silently, the job completed normally, and the drill would have "passed" having killed nothing —
the exact class of failure the brief warns about, found in my own instrument. The kill now walks
`/proc` and uses `kill`, a shell **builtin**, and the drill **aborts** unless it can name the pids it
killed (it printed `killing 651`, `killing 689`).

**What the real drill showed.** Killed mid-`loading`; the job sat in `loading` with a lease held by a
process that no longer existed. Fly's init restarted the CMD by itself (`Starting init` → `[worker]
starting` → `connected`, all inside 9s, **no human**), and the restarted worker reclaimed the job
once the lease expired: `attempt=2`, then `validating → fetching → building → loading → ready`.
**Postgres never held a partial league**, because `load_league` is one transaction and it is the last
thing that runs — the pre-drill and post-drill counts are identical on every table. The truncated raw
was **repaired by the retry** (back to 18 matchups files from 1), which is defect B's fix firing in
production rather than in a gate.

**Reclaim latency is `LEASE_SECONDS` + up to `IDLE_WAKE_SECONDS`** — 120s + ≤60s; measured **130s**.
That is the price of nobody intervening, and it is a number rather than a hope.

### Will's check #4 — the empty queue, as a number

**Idle cost is ~0 queries.** The worker does not poll: it blocks on `LISTEN jobs_new` and wakes at
most once a minute, so an idle day is **1,440 wakeups** (one `reap` + one `lease` each ≈ **2,880
statements/day**, each an index probe on a table that is currently 5 rows) — against the 11
analytical queries **every anonymous visitor** already fires. A 2s poll would have been 43,200
queries/day; a 30s poll would have added ~15s to a 10s build. LISTEN removes the trade.

**Connections: one, held.** STATUS flags "two connection pools against a free-tier Postgres" as a P6
item — an always-listening worker makes it **three**, and unlike the other two it is never idle-closed
by design. Recorded rather than solved.
