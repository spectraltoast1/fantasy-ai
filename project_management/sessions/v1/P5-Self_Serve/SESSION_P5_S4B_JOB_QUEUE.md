## Why the queue is the session, and the connect flow is not

S4a built `onboard_league.onboard(lid, season, …)` — a complete, callable, proven entry point that
catalogs and commits. **What does not exist is any way to invoke it except a human typing
`fly ssh console`.**

**And the API physically cannot invoke it.** `api/requirements.txt` is deliberately minimal — *"no
polars/nflreadpy/anthropic"* — and the worker has **no `[http_service]`**. So the API cannot run a
build and cannot call the machine that can. **That, not latency, is the forcing function for a
queue.** S0's 8.4–10.3s would fit in a request; the two machines not being able to talk does not.

**The one genuinely new shape here is a long-running leasing process.** `Dockerfile.worker:80` is
`CMD ["sleep", "infinity"]` — the machine is always on (that is the ~$7/mo) and does nothing. Turning
that into a process that leases work is an architectural change and gets its own session, exactly as
the boundary did before the worker.

**Everything downstream is known-shape work on top:** S4c's `POST /api/connect` inserts a row;
**S4d's weekly cadence inserts rows too.** That is the quiet win — *"what does the GitHub Action
poke?"*, which the startup doc left open, **dissolves**: it pokes Postgres, which it already has
credentials for. Do not build either here.

## 1 · THE GUARD — first commit, before anything else

**S4a made the laptop the machine with the stale catalog, and nothing stops it publishing that.**
Recomputed 2026-08-14: laptop `_catalog()` = **32** rows, production `league_catalog` = **33**.
`connected_catalog.parquet` exists only on the worker's volume, and `read_connected_catalog()`
returns an **empty frame** when absent — silently, by design.

So today `build_db --reload-manifest` on the laptop deletes the connected league's catalog row, and
`--load` drops its data rows as well. The existing guard refuses on the **worker**, which after S4a is
the machine that is *right*.

- **`reload_manifest()` and `load()` must refuse when Postgres holds `league_id`s absent from the
  local `_catalog()`** — naming them, with the operator step. Same shape as every other guard here:
  compare, then raise.
- **Prove it bites both halves:** it refuses against the real 33-vs-32 drift, and it still permits a
  run when local and Postgres agree. A refusal alone proves nothing.
- **Two traps to state in the code, not just the report.** The documented remedy for an un-emitted
  column (`--emit` + `--load`) *is* this failure. And the laptop's `build_db --verify` now
  legitimately reports **VERIFY FAILED** (S4a finding B) — so the one alarm that would catch this has
  already been explained away as expected, and an operator reconciling it with `--load` walks into
  the loss. The guard's message must say so.

## 2 · The `jobs` table — and it does NOT go in `schema.sql`

- **It belongs in `api/auth_schema.sql`**, applied by `init_auth_schema`. This is load-bearing and
  that file already explains why: `serve/schema.sql` is **generated by `build_db --emit`** and applied
  by `--load`, **which DROPs every table it names.** A jobs table in there would be destroyed by the
  next full load — *"protected by how the code works rather than by anyone remembering."*
  Add it to `_TABLES` (one list entry, per that file's own design) and inherit the column and
  cascade assertions.
- **The state column carries the full set** — `queued → validating → fetching → building → loading →
  ready | rejected | failed` — because S6's failure drills want it and a column is free.
  **Do NOT build per-stage UI or per-stage semantics.** A ~10s build on a spinner does not need six
  user-visible states, and S4c decides what a person actually sees.
- **`validating` is a SLOT, not a feature.** S5 owns preflight scope validation and the graceful
  rejection copy. S4a already shipped the loud half — `onboard_league.assert_in_scope` declines
  non-redraft and says in its own docstring *"this is the loud stop, not the product's answer. S5 owns
  the graceful user-facing rejection."* **Do not write S5 here.** A job that raises out of scope lands
  in `rejected` with the reason recorded; making that legible is S5's.
- **What a row must carry:** enough that a job is re-runnable and attributable, and enough that
  `failed` can be told from `rejected` without reading logs. **State the fields you chose and why**;
  do not copy a list from this brief.

## 3 · The lease — one worker, and the correctness is in the SQL

- **`SELECT … FOR UPDATE SKIP LOCKED`** is the right primitive and it is the one to name explicitly.
  The worker is a **stateful singleton** (a Fly volume attaches to exactly one machine — the ADR), so
  a second concurrent worker is not possible *today*. **Build the lease as if it were**, because S4d
  adds a second producer and the GHA runner is a third machine that already exists.
- **A lease must expire.** The drill below kills a job mid-run; if the lease is held forever, that
  league is stuck until a human intervenes — which is the thing this session exists to remove.
  **Choose a timeout against S0's measured 8.4–10.3s plus the 80s dossier fan-out, and say how you
  chose it.**
- **Idempotency is already paid for.** `classify()` returns `cold` / `reonboard` / raise, and S4a
  proved a re-onboard is value-identical with no duplicate row. So a job retried after a crash is
  safe by construction — **verify that claim rather than inheriting it**, and say which of the two
  paths a retry actually takes.

## 4 · The worker process — `sleep infinity` becomes a loop

- **Replace the CMD**, and keep the box a job box: no HTTP, no health check, nothing listening.
- **It must survive an empty queue, a bad job, and a restart** without a human. A crash loop on one
  malformed row is an outage for every other user's league.
- **`STORE_ROLE=worker` must still hold** — it is set in both `fly.worker.toml [env]` and the image
  (belt and braces, deliberately). A long-running process is a new way to lose an env var; assert it
  at startup and refuse to lease without it.
- **This is a worker redeploy.** "Merged" is not "deployed"; the worker has no URL, so nobody outside
  the session can check it. Say what you deployed and how you confirmed it.

## 5 · Proving it — the DoD is the absence of a human

1. **A job row inserted by hand is picked up, run to `ready`, and the league is in Postgres — with
   nobody touching `fly ssh` after the insert.** That is the whole session in one sentence.
2. **The states advance and are observable** — a reader can tell from the table alone what happened
   and when, without the worker's stdout.
3. **The kill drill.** Kill a job mid-run. The lease expires, the job is retryable, and **there is no
   half-built league** — the P5 risk register's exact words: *"never a half-built league that looks
   complete."* Check the store **and** Postgres, by count.
4. **A rejected job is distinguishable from a failed one**, and neither is silent.
5. **Nothing else moved:** the demo, every other league, and `league_catalog` unchanged by count.
   Signed-out live prod still returns exactly the demo.

**Use a re-onboard for the happy path, not a fresh league.** S4a's Rex Lumber
(`1258181662160719872`) is connected and its re-onboard is proven value-identical, so it exercises the
queue without adding a second stranger's league to production. **If you need a cold run to prove the
`cold` branch, enumerate a candidate the way S4a did — and do NOT re-run the corpus discovery crawl.**

**Verify the instrument.** A queue that reports success because it leased nothing, or because
`classify()` short-circuited to `reonboard` and every stage no-opped, is this project's most-repeated
failure — three times now (`_db_max_as_of`, the parity run's seven skips, `check_onboard`'s first
prove-bites). **Show the work happened.**

## Scope guard

Does **NOT**: build `POST /api/connect`, `GET /api/connect/{id}`, identity acquisition, or any
frontend (**S4c**); build the weekly cadence or touch `.github/workflows/weekly_refresh.yml`,
`MY_USERNAME` or `LEAGUE_ID` (**S4d**); write S5's preflight validation or its rejection copy; add
`--delete` to `scripts/users.py` (**S4c**); fix the null-seat collision (S4a finding F — **S4c**);
run `--emit` or `--load` against production; touch engine constants, any transform's maths, the
corpus, the frozen corpus manifest, or `demo_manifest.parquet`'s 31 rows.

**Named release valve:** if the 3-commit cap bites, ship **the guard + the table + the lease + the
worker loop + DoD 1–2**, and defer **the kill drill (DoD 3)** to a short follow-up — **and say so in
the report.** The guard is **not** the valve; it ships first or the session does not ship. S4a's
report was clean about the valve it did not take; hold that standard.

**Bank before anything destructive (CODING_BIBLE §6)** — the guard's prove-it-bites compares against
production Postgres. Commit first.
