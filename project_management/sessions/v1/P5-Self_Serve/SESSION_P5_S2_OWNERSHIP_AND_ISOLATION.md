> **What this session does:** makes an account *mean* something. S1/S1b built a front door; every read
> behind it is still open to everyone, and an unauthenticated request still resolves to **Will's real
> league** by name-resolution accident. S2 gives leagues owners, scopes every read to the caller, and
> proves a stranger cannot reach someone else's league.

> **Why it is split.** This is the security session and the project's standing instruction is *do not let
> a fast cadence compress it — isolation bugs fail silently.* One session that both invents the ownership
> model and rewrites every read's authorization ends with a green run and no way to tell which half the
> green came from. **S2a builds the model and proves the catalog. S2b scopes the reads and spends its
> whole proof budget on an adversarial matrix. S2c is a punch list.** Run them in order.

## The settled model (decided with Will, 2026-08-05 — do not re-derive)

**Visibility is one predicate:**

```
visible(league) = (league_id == DEMO_LEAGUE_ID)  OR  (owned by caller  AND  season == current)
```

- **There is exactly ONE public league** — the demo. Everything else is private and requires ownership.
  This inverts the old model: the 31 demo slices were a *demonstration that multi-league works*, not a
  product surface.
- **`DEMO_LEAGUE_ID` is a config value, not a table.** `application/config.py` + a Fly secret or `[env]`,
  resolved env-first exactly like `ACCESS_CODE`. One value, no migration, no seeding, and it cannot drift
  from a loader-generated artifact. It points at real LoRP 2025 (`1182101676608823296`) **today** and gets
  repointed at the anonymized clone when that exists — one line, whenever.
- **"Current season" comes from Sleeper's `/v1/state/nfl`** (`season`), not a hardcoded constant. It rolls
  over during the preseason, which is the desired behaviour — 2026 was already "current" in early August.
- **The demo is the deliberate exception to the current-season rule** — it is a 2025 league in the 2026
  season. Do **not** implement visibility as a global `season = current` filter; the demo term comes first
  and is season-independent. Implemented as a global filter, the demo vanishes and it looks like an auth bug.
- **The 31 corpus slices stay in the database.** They are engineering fixtures — `compute_demo_slices`,
  `build_demo_manifest`, B6's 31/31 verification and `check_scoped_reload`'s parity oracle all depend on
  them. **Only the public catalog shrinks to one.** Nothing is deleted.

**What people see:**

| state | lands on | can switch to |
|---|---|---|
| signed out | the demo (it is also the landing page for now) | nothing else |
| signed in, ≥1 owned current-season league | **their own league** | the demo, and their other leagues |
| signed in, no league yet | the demo (this is the empty state) | — |

The demo staying reachable after sign-in is deliberate: S5 declines out-of-scope leagues, so a user can
hold an account with nothing of their own to look at.

**The season selector goes.** Prior seasons are corpus, not product — there is no user value in browsing
last year. `season` is **not a SQL filter anywhere** in the read layer (verified: zero hits; a redraft
`league_id` already pins one `(league, season)` slice), so removing it is a frontend + catalog change and
touches no data path. The **league** switcher stays — a user may own several current-season leagues. The
**week** switcher stays.

## Decisions I made for you (Code: follow unless you hit a reason not to)

1. **Ownership is a hand-written table.** `public.user_leagues (user_id uuid references auth.users on
   delete cascade, league_id text, created_at)`, PK `(user_id, league_id)`, in `api/auth_schema.sql`
   beside `app_users` and `signup_attempts`. **Not** in `serve/schema.sql`: that file is generated by
   `--emit` and applied by `--load`, which DROPs every table it names. This project has already lost
   `ros_player_band`'s RLS to exactly that.
2. **No `league_visibility` table.** An earlier draft of this brief proposed one; it is unnecessary once
   there is exactly one public league. Config beats a table here.
3. **Authorization is one predicate, in one place** — `slice_params`, the dependency every read already
   takes. Not repeated per route. One seam, one place to get it wrong, one place to test.
4. **An unowned league returns the SAME 404 as a league that does not exist.** `slice_params` already 404s
   an unknown `league_id`; route the unauthorized case into that identical response. A 403 would confirm
   the league exists, which is an enumeration oracle — Sleeper league IDs are guessable, so a 403/404 split
   lets anyone probe which leagues are on the platform. Same reasoning that made S1b's refusal uniform.
5. **Signed-out resolves to `DEMO_LEAGUE_ID` explicitly.** Today `league_id=None` falls through
   `MY_USERNAME` to the is_mine league — an anonymous visitor lands on Will's real league by accident of
   name resolution. Make it explicit. `MY_USERNAME` stays only as the resolver for Will's own viewer seat.
6. **`viewer_roster_id` stays caller-supplied but must be validated against a visible slice.** Viewing your
   own league "as" another manager is a feature the dossiers depend on; reaching into a league you cannot
   see is the bug. Validate the slice, not the seat.
7. **Grant/revoke is operator tooling now, the connect flow later.** `scripts/users.py` gains
   `--grant <email> <league_id>` and `--revoke`. S4's connect flow will write the same row; S2 must not
   wait on S4 to have data to test with.
8. **Do not build RLS policies.** Settled: isolation is **API-layer**. The app connects as an owner role
   that bypasses RLS, so a policy build denies nothing today and reads as protection that isn't there.
   (S2c still fixes the *emit* drift — that is about not silently losing a property, not relying on it.)

## S2b — sketch now, paste-block written after S2a lands

Deliberately not written in full: its authorization call sites depend on the shape S2a actually ships, and
writing a detailed brief against an assumed shape is how S1 went wrong.

**Scope:** move the visibility predicate into `slice_params` so every read inherits it; route the
unauthorized case into the existing unknown-`league_id` 404; validate `viewer_roster_id` against a visible
slice; move viewer identity from a *league* property to a **user × league** property; **remove the season
selector** from the frontend and flatten the catalog's lineage→seasons grouping.

**Its whole proof budget goes to one artifact:** a committed `application/api/check_isolation.py` running
**every read endpoint × {signed-out, owner, other user}** and asserting the matrix — the `check_signup` /
`check_matchup_result` precedent, so isolation gets a re-runnable gate rather than a one-off transcript.
It must include a **prove-bites** block: run the checks against the *unscoped* behaviour and require every
one to fail. An isolation check that has never failed has not been tested.

**Name the endpoints explicitly in the matrix.** "All reads" in a report means "the ones the loop happened
to reach"; a hard-coded list asserted against the router's registered routes cannot silently skip one.

## S2c — punch list (can ride with S2b or go alone)

1. **`--emit` must emit `ALTER TABLE … ENABLE ROW LEVEL SECURITY`** for every table it names, so an
   out-of-band property stops being destroyed by the next full load; then `ros_player_band` regains RLS.
   *Prove it bites: drop RLS by hand, re-run `--emit`/`--load`, show it comes back.*
2. **Reorder the signup rate limit** (S1b audit): validate the access code **before** the email counter, so
   five garbage-code attempts against a known address cannot lock a real person out of sign-in for an hour.
   Keep counting failures by email and IP; never let a *correct* code be refused by the email counter.
3. **Confirmed accounts with nobody behind them** — `signup.py` creates with `email_confirm: true` before
   the link is known to send, so a mailer failure leaves a confirmed account. Decide whether the ownership
   model cares; if not, write down that it doesn't.

## Definition of done (S2a)

1. `user_leagues` exists, applied by `init_auth_schema`, and is absent from the generated `serve/schema.sql`
   — asserted, as `app_users` already is.
2. `DEMO_LEAGUE_ID` resolves env-first and repointing it is one config change.
3. Two real accounts, two different catalogs, demonstrated — including the revoke and the prior-season case.
4. The demo is visible in every state, including signed-out, and survives the current-season term.
5. Signed-out `/api/leagues` returns exactly the demo; a signed-in user with a league gets their own first.
6. `--grant` / `--revoke` work, are idempotent, and `--list` shows ownership.
7. Every other read is value-identical for signed-out and for user A.
8. Merged, **redeployed**, confirmed live.

## Notes / gotchas

- **There is no second league to test with until you make one.** Grant user B a corpus league that is not
  the demo. Decide it early — "we couldn't test cross-user isolation" is not an acceptable outcome here.
- **`slice_exists` is doing double duty today** — it is both the existence check and, by accident, the
  authorization boundary, because `demo_manifest` happens to contain only the demo set. A real user's
  league will not be in that manifest until S4 catalogs it. S2a must not deepen the coupling; S2b separates it.
- **Do not let the fast cadence compress this.** An isolation bug does not announce itself — the app looks
  perfect while showing the wrong person's data. The adversarial matrix in S2b is the deliverable, not a
  formality around it.
