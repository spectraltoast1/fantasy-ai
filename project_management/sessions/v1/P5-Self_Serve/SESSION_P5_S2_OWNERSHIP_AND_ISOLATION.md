# V1 · Project 5 · Session S2 — Ownership + API-layer isolation — a brief for Code

**Last reviewed:** 2026-08-05 · **Status:** S2a ready to run · **Owner:** Code drives; Will supplies a

**Prior:** `SESSION_P5_S1B_AUDIT.md` (its findings are this session's inbox).

> **What this session does:** makes an account *mean* something. S1/S1b built a front door; every read
> behind it is still open to everyone, and an unauthenticated request still resolves to **Will's real
> league** by default. S2 gives leagues owners, scopes every read to the caller, and proves a stranger
> cannot reach someone else's league.

> **Why it is split.** This is the security session and the project's own standing instruction is *do not
> let a fast cadence compress it — isolation bugs fail silently.* One session that both invents the
> ownership model and rewrites every read's authorization would end with a green run and no way to tell
> which half the green came from. **S2a builds the model and proves the catalog. S2b scopes the reads and
> spends its whole proof budget on an adversarial matrix. S2c is a punch list.** Run them in order; do
> not merge a into b.

## Decisions I made for you (Code: follow unless you hit a reason not to)

1. **Ownership is a hand-written table, not a generated one.** `public.user_leagues (user_id uuid
   references auth.users on delete cascade, league_id text, created_at)`, PK `(user_id, league_id)`,
   living in `api/auth_schema.sql` beside `app_users` and `signup_attempts`. **Not** in
   `serve/schema.sql`: that file is generated by `build_db.py --emit` and applied by `--load`, which
   DROPs every table it names. This project has already lost `ros_player_band`'s RLS to exactly that.
2. **Public/private is its own small table, for the same reason.** `public.league_visibility (league_id
   text primary key, is_public boolean not null default false)` in `auth_schema.sql`, seeded from
   today's `demo_manifest` rows. Do **not** encode "public" as "present in `demo_manifest`" — the
   manifest is a generated, loader-owned artifact, and S4 will start putting *users'* leagues in it.
   A visibility decision must not live somewhere a reload can rewrite.
3. **Authorization is one predicate, in one place.** A slice is visible iff
   `league_visibility.is_public` **OR** `(caller, league_id) ∈ user_leagues`. It belongs in
   `slice_params` — the dependency every read already takes — not repeated per route. One seam, one
   place to get it wrong, one place to test.
4. **An unowned league returns the SAME 404 as a league that does not exist.** `slice_params` already
   404s an unknown `league_id`; route the unauthorized case into that identical response. A 403 would
   confirm the league exists, which is the same enumeration oracle S1b refused to build.
5. **Signed-out resolves to the PUBLIC DEMO, explicitly.** Today `league_id=None` falls back to
   `MY_USERNAME`'s roster and the is_mine league — i.e. an anonymous visitor lands on Will's real
   league by name-resolution accident. Make the signed-out default an explicit "the public demo slice",
   with `MY_USERNAME` retained only as the resolver for Will's own viewer seat.
6. **`viewer_roster_id` stays caller-supplied but must be validated against a visible slice.** Viewing
   your own league "as" another manager is a feature (the dossiers depend on it); reaching into a league
   you cannot see is the bug. Validate the slice, not the seat.
7. **Grant/revoke is operator tooling now, the connect flow later.** `scripts/users.py` gains
   `--grant <email> <league_id>` and `--revoke`. S4's connect flow will write the same row; S2 must not
   wait on S4 to have data to test with.
8. **Do not build RLS policies.** Settled: isolation is **API-layer**. The app connects as an owner role
   that bypasses RLS, so a policy build would be defence-in-depth that denies nothing today and reads as
   protection that isn't there. (S2c still fixes the *emit* drift — that is about not silently losing a
   property, not about relying on it.)

## S2b — sketch now, paste-block written after S2a lands

Deliberately not written in full yet: its authorization call sites depend on the shape S2a actually
ships, and writing a detailed brief against an assumed shape is how S1 went wrong.

**Scope:** move the visibility predicate into `slice_params` so every read inherits it; make the
unauthorized case return the existing unknown-`league_id` 404; validate `viewer_roster_id` against a
visible slice; move viewer identity from a *league* property to a **user × league** property.

**Its whole proof budget goes to one artifact:** a committed `application/api/check_isolation.py` that
runs **every read endpoint × {signed-out, owner, other user}** and asserts the matrix — following the
`check_signup` / `check_matchup_result` precedent, so isolation has a re-runnable gate rather than a
one-off transcript. It must include a **prove-bites** block: run the checks against the *unscoped*
behaviour and require every one to fail. An isolation check that has never failed has not been tested.

**Name the endpoints explicitly in the matrix.** "All reads" in a report means "the ones the loop
happened to reach"; a hard-coded list that must match the router's registered routes cannot silently
skip one.

## S2c — punch list (can ride with S2b or go alone)

1. **`--emit` must emit `ALTER TABLE … ENABLE ROW LEVEL SECURITY`** for every table it names, so an
   out-of-band property stops being destroyed by the next full load. Then `ros_player_band` regains
   RLS. *Prove it bites: drop RLS by hand, re-run `--emit`/`--load`, show it comes back.*
2. **Reorder the signup rate limit** (from the S1b audit): validate the access code **before** the
   email counter, so five garbage-code attempts against a known address can no longer lock a real
   person out of sign-in for an hour. Keep counting failures by email and IP; never let a *correct*
   code be refused by the email counter.
3. **Confirmed accounts with nobody behind them** — `signup.py` creates with `email_confirm: true`
   before the link is known to send, so a mailer failure leaves a confirmed account. Decide whether
   the ownership model cares; if not, write down that it doesn't.

## Notes / gotchas

- **There is no second league to test with until you make one.** Grant user B one of the existing demo
  slices and mark that slice non-public for the duration, or grant B a corpus league that isn't in the
  demo set. Decide it early — it shapes the test, and "we couldn't test cross-user isolation" is not an
  acceptable outcome for this session.
- **`slice_exists` is doing double duty today** — it is both the existence check and, by accident, the
  authorization boundary, because `demo_manifest` happens to contain only public slices. S2a must not
  deepen that coupling; S2b separates it properly.
- **The demo must stay open to logged-out visitors.** It is a settled product requirement, and it is
  also the thing that makes the isolation proof meaningful: "everything is denied" is not the goal.
- **Do not let the fast cadence compress this.** An isolation bug does not announce itself — the app
  looks perfect while showing the wrong person's data. The adversarial matrix in S2b is the deliverable,
  not a formality around it.
